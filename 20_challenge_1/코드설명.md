# 20C10 도전과제 — 적외선 거리센서 자동 곡선맞춤

스프레드시트에서 손으로 하던 실습 1·2(거리별 전압 측정 → 추세선 → 방정식 옮겨 적기)를 아두이노 혼자 하게 만들었다. 시리얼 모니터에서 방식과 차수를 고르고, 탁구공을 0~30cm에 5cm씩 옮기며 엔터를 누르면, 최소제곱법으로 곡선을 맞춘 뒤 **그대로 붙여 넣으면 컴파일되는 `volt_to_distance()` 함수**를 출력한다.

## 1. 사용법

시리얼 모니터: **1000000 baud**, 줄 끝은 **"새 줄(Newline)"**. "line ending 없음"이면 빈 엔터가 아무것도 보내지 않아서 측정이 안 된다.

1. `method` 입력: 1 = ADC 다항식, 2 = 1000/ADC 다항식. 그냥 엔터면 괄호 안 기본값.
2. `degree` 입력: 1~6.
3. `[1/7] put the ball at 0 cm` … `[7/7] 30 cm`까지 공을 옮기고 엔터. 잘못 쟀으면 `r` 입력 → 직전 점을 다시 잰다.
4. 7점이 끝나면 엔터 한 번 더 → 곡선맞춤 결과 출력.
5. 이후 메뉴
   - `f`: 같은 데이터로 방식/차수만 바꿔 다시 맞춤 (R² 비교, 과적합 관찰)
   - `m`: 처음부터 다시 측정
   - `t`: 테스트 모드. 엔터마다 현재 거리를 맞춘 식으로 계산해 출력 → 실습 3(A 255mm, B 155mm, C 55mm) 확인용. `q`로 나감.

출력 예 (시뮬레이션):

```
  dist(mm)     ADC   fit(mm)   err(mm)
         0   685.2       0.0       0.0
        50   460.1      49.9      -0.1
       ...
R^2 = 1.00000, RMSE = 0.19 mm

//////// copy from here ////////
// curve_fitting: polynomial of 1000/ADC, degree 2, R^2 = 1.00000, RMSE = 0.19 mm
float volt_to_distance(unsigned int a_value)
{
  if (a_value < 1) a_value = 1;
  float t = (1000.0 / a_value - 3.540282E+00) / 2.080854E+00;
  return 1.472641E+02 + t * (1.500557E+02 + t * 2.827032E+00);
}
//////// copy to here ////////
```

`copy from here`~`copy to here`를 `20_example_2`의 `volt_to_distance()` 자리에 붙이면 끝이다. 측정값은 탭으로 구분된 `ADC / Distance(mm)` 표로도 찍어 주므로, 스프레드시트 A1에 붙여 넣어 실습 2의 추세선과 비교할 수 있다.

## 2. 측정

점 하나당 `ir_sensor_filtered(31, 0.5, 0)`(실습 1의 중앙값 필터)를 10번 불러 평균낸다.

- 중앙값: 적외선 센서의 스파이크 노이즈 제거. n을 홀수(31)로 해서 중앙값이 실제 샘플 하나가 되게 했다.
- 10번 평균: ADC는 정수라서, 평균을 내면 소수 부분까지 얻어 맞춤이 조금 더 정확해진다.
- 10개 중앙값의 최대-최소(spread)를 같이 찍고, 10을 넘으면 "unstable"이라고 알려 준다. 공이 흔들렸거나 레일에서 비뚤어진 경우다.

## 3. 곡선맞춤 방식

### 방식 1: ADC 다항식

dist = c0 + c1·x + c2·x² + … (x = ADC). 스프레드시트의 "다항" 추세선과 같은 모델이다. 결과 아래에 같은 식을 x의 거듭제곱으로 풀어 쓴 `y = ...x^3 + ...` 형태도 찍어서 시트 추세선 식과 바로 비교할 수 있다.

### 방식 2: 1000/ADC 다항식

Sharp 센서는 거리가 대략 `k / ADC`에 비례한다(17주차 식 `6762/(a-9) - 4`도 이 꼴). 그래서 u = 1000/x로 바꿔 놓고 다항식을 맞추면 낮은 차수로도 잘 맞는다. 시뮬레이션(센서 모델 + 노이즈)에서 방식 1 3차는 RMSE ≈ 3mm, 방식 2 2차는 ≈ 0.2mm였다. 1000을 곱한 건 u가 1~10 근처가 되도록 크기만 맞춘 것이다.

## 4. 계산 방법 — 왜 그냥 정규방정식을 안 썼나

아두이노 우노의 `float`/`double`은 둘 다 32비트(유효숫자 약 7자리)다.

1. **정규화:** x를 그대로 쓰면 x⁶ ≈ 1000⁶ = 10¹⁸이라 작은 항이 다 묻힌다. 그래서 t = (x − 중간값) / 반폭으로 바꿔 t를 [−1, 1] 안에 넣고 t에 대해 맞춘다.
2. **QR 분해(수정 그람-슈미트):** 정규방정식(AᵀA c = Aᵀy)은 조건수를 제곱해서 float로는 고차에서 틀어진다. 대신 A = QR로 분해하고 R c = Qᵀy를 역대입으로 푼다. 7×7 이하라 메모리는 몇백 바이트다.
3. **출력도 t 형태:** `t * (c1 + t * (c2 + ...))` 꼴(호너 방식)이라 곱셈 수가 적고, 큰 수끼리 빼는 상쇄 오차가 없다. 시트처럼 x³ 형태로 쓰면 x=600일 때 2×10⁸ 같은 값끼리 더하고 빼게 돼서 float에서 오차가 커진다. 그래서 풀어 쓴 식은 비교용으로만 찍는다.

계수는 `print_num()`으로 `-1.234567E-03` 같은 C 지수 표기(유효숫자 7자리)로 찍는다. `Serial.print(0.0000012, 6)`은 `0.000001`이 되어 버리기 때문이다.

## 5. 과적합 체크

- **R², RMSE**와 점별 오차표를 같이 찍는다. R²만 보면 차수를 올릴수록 무조건 1에 가까워진다.
- 7점에 6차를 고르면 모든 점을 그대로 지나가서 R² = 1이 된다. 이때 "Overfitting" 경고를 띄운다.
- **단조성 검사:** ADC가 커질수록(공이 가까울수록) 거리는 줄어야 한다. 측정 범위를 100칸으로 나눠 곡선이 중간에 0.5mm 이상 올라가면 "the curve goes up somewhere" 경고를 띄운다. 시뮬레이션에서 6차 다항식은 R² = 1인데도 이 경고가 떴다 — 점 사이에서 곡선이 출렁인다는 뜻이다.
- 같은 ADC 값이 여러 번 나와 열이 종속이면(차수 대비 서로 다른 점이 부족) "Fitting failed … Lower the degree."로 멈춘다.

## 6. 검증

- `arduino-cli`로 Uno 대상 컴파일: 경고 없음, 플래시 15,368B(47%), 전역 RAM 324B(15%).
- PC에서 `Serial`/`analogRead`를 흉내 낸 시뮬레이터로 전체 흐름(메뉴, `r` 다시 재기, CR+LF 줄 끝, 방식·차수 변경, 테스트 모드)을 돌려 봤다. 테스트 모드에서 255/155/55mm가 255.8/154.8/55.1mm로 나왔다.
- 출력된 호너 식과 풀어 쓴 식에 같은 x를 넣어 값이 소수 셋째 자리까지 같은지 확인했다.
- 실제 센서·레일에서는 아직 안 돌려 봤다. 실제 값은 수업 시간 측정으로 확인해야 한다.
